# Release Notes

What changed in each release of PAIR. If you are updating from an earlier
version, read the [Upgrade Guide](upgrade-guide.mdx) as well: it covers the
steps some machines need.

Notes for releases before 1.0.0 are on
[GitHub Releases](https://github.com/NVIDIA/Personal-AI-Router/releases).

## PAIR Plus 1.3.0

See how fast every model is, what each model is, and what it is allowed, and
take a node out of service without losing work. Download it from the
[PAIR Plus releases page](https://github.com/B-E-L-I-E-V-E/Personal-AI-Router-Plus/releases).

### What's New

- **Performance.** A new tab with a stopwatch icon, next to **Settings**, has a
  card per node: what it is running now, which models it has loaded, and each
  model's tokens in and out, reading and writing speed, time to first token
  and thinking time. The stopwatch on each node card shows its requests live.
  **Run benchmark** compares models with four fixed prompts. Only counts and
  timings are kept, never text.
- **About this model…** in each model's menu shows what its engine reports
  (description, tags, capabilities, quantization, context, licence) with links
  to the model's pages, for models on any node. **Look up on the web** fills
  what the engine leaves out from the model's own page.
- **Each model's settings on its row**: sessions at once, the window per
  session, the response and the post context, on every node.
- **Pause, Stop and Resume** on each node card. Paused nodes finish what they
  are running; stopped nodes cancel it. Requests go to other nodes meanwhile.
- **APIs.** `/pair/v1/performance` (with `/live` and `/benchmark`) and
  `/pair/v1/node/state`. The new [HTTP API Guide](api.mdx) shows every call
  with the exact JSON a node returns.

### Changed

- The repository moved to `B-E-L-I-E-V-E/Personal-AI-Router-Plus`. The old
  address redirects, and the app now checks the new one for updates.
- The OpenAPI reference describes PAIR's error object as it is sent:
  `{"error": "…"}`, with a `code` where it helps.

Refer to [Model Performance and Benchmarks](performance.mdx),
[Pausing and Stopping a Node](node-state.mdx) and
[Managing Engines](engine-lifecycle.mdx) for details.

## PAIR Plus 1.2.0

Each model's context capacity is now set from its own menu and sized from the
node's memory, with room kept for the model's reply. Download it from the
[PAIR Plus releases page](https://github.com/B-E-L-I-E-V-E/Personal-AI-Router-Plus/releases).

### What's New

- **Context & sessions per model.** Each model's menu (**…**) has **Context &
  sessions…**: sliders for the context window, the room kept for the reply,
  sessions at once and the memory kept free, with GPU and system memory bars.
  The sliders and bars turn red when the settings need more than the node
  has, and such a plan can still be saved.
- **How much text fits.** A table follows the sliders, showing how much text
  fits in one post, in the response and in the whole window, in words, pages
  and characters, for English, code, JSON, Chinese, base64, IDs and emoji.
- **Room for the reply.** Every session keeps part of its window for the
  model's reply (8,192 tokens by default). PAIR refuses a conversation that
  outgrows the rest, stops Ollama from silently cutting long conversations,
  and caps replies that set no length of their own.
- **Mixture-of-experts models** can keep their expert weights in system memory
  on llama.cpp, leaving the GPU for more sessions.
- **APIs.** The capacity API carries each model's reply budget, and the session
  API reports the room a session's next post has.

### Changed

- **Every session gets the model's whole context window.** In 1.1.0 a model's
  context was divided among its sessions; now the window belongs to each
  conversation, and the node's memory decides how many run at once.
- **Settings → Sessions** keeps the session policy and live sessions, each
  showing the room its next post has. A model's capacity is set only in its
  menu.

Refer to [Sessions and Context Capacity](sessions.mdx) for details.

## PAIR Plus 1.1.0

The first release of PAIR Plus, an independent fork of PAIR 1.0.0. Download it
from the
[PAIR Plus releases page](https://github.com/B-E-L-I-E-V-E/Personal-AI-Router-Plus/releases).

### What's New

- **Request IDs.** Every response carries an `X-Request-ID`, yours or one PAIR
  creates, also recorded on the job and the logs.
- **Sessions and agents.** Send `X-PAIR-Session-ID` on each turn and each one
  goes back to the node that served the last, so the engine reuses its cached
  prompt. `X-PAIR-Agent-ID` names the agent that owns the session.
- **Session lifetime.** A session ends after 10 idle minutes by default (1 to
  60), stays open for any request, a keepalive, or a request still running, and
  can be ended at once. Ending it cancels its running requests.
- **Context capacity.** Divide a model's context among a set number of sessions.
  New sessions go to another node or wait when a model is full, and a session
  that outgrows its share is asked to shorten its conversation. Each node
  enforces its own capacity.
- **Settings → Sessions.** Edit the session policy and each model's capacity,
  and see or end live sessions.
- **Signed macOS builds and PAIR Plus updates.** macOS builds are signed with a
  Developer ID and notarized, and every build updates from PAIR Plus releases.

Refer to [Sessions and Context Capacity](sessions.mdx) for details.

### Compatibility

PAIR Plus nodes and PAIR 1.0 nodes work together in one cluster. A 1.0 node
serves requests from a PAIR Plus node normally but does not enforce context
capacity. Moving a machine to PAIR Plus is covered in the
[Upgrade Guide](upgrade-guide.mdx#moving-a-machine-to-pair-plus).

## 1.0.0

This release brings llama.cpp and RTX Spark support to PAIR, and establishes
its public development and contribution workflow on GitHub.

### What's New

- **llama.cpp support.** Install and manage llama.cpp directly from PAIR,
  download compatible GGUF models from Hugging Face, and route inference
  requests across paired devices. Refer to
  [Managing Engines](engine-lifecycle.mdx).
- **Engine launch options.** Customize the launch arguments and environment
  variables of PAIR-managed engines, on this device or a paired one. Tune
  settings such as context size where the engine supports them. Refer to
  [Engine Settings](engine-settings.mdx).
- **RTX Spark support.** PAIR's Windows on ARM build has been validated with
  llama.cpp and CUDA on RTX Spark N1X hardware.
- **Improved terminal experience.** The terminal interface has a redesigned
  layout organized around each device, so you can manage engines, download
  models, and pair devices from one place. A new **Jobs** tab follows inference
  work across paired devices and runs the Inference Demo, giving headless
  machines the same core tools as the desktop app. Refer to
  [Terminal Interface](terminal-interface.mdx).

### Compatibility Notes

- **Browser clients.** PAIR's local endpoints now follow each engine's CORS
  policy instead of allowing every browser origin. A browser-based client may
  need the engine configured to allow it — for Ollama, set `OLLAMA_ORIGINS` in
  the engine's launch options.
- **The macOS app is now NVIDIA PAIR.** The new `NVIDIA PAIR.app` installs
  beside the old `PAIR.app`, so remove the old one to keep just one copy. Your
  settings, cluster membership, and downloaded models carry over.
- **LM Studio installed by an earlier PAIR.** It keeps working as before. PAIR
  now removes only engines it has a record of installing, and earlier versions
  kept no record, so uninstalling or resetting PAIR leaves that LM Studio in
  place. You can remove it from `~/.lmstudio` yourself if you no longer want it.

The [Upgrade Guide](upgrade-guide.mdx) walks through each of these.

### Targeted Bug Fixes

- Uninstalling LM Studio from PAIR, or uninstalling PAIR with its data, no
  longer deletes the models you downloaded. They stay in `~/.lmstudio/models`,
  just as Ollama's stay in `~/.ollama` and llama.cpp's in `~/.llamacpp`.
